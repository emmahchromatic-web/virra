① Activity data sources — priority order
Manual logging is the last resort, not the default. The app passively collects from HealthKit in the background — users only interact when there's genuinely no data.
Primary
Apple Watch
Workouts auto-sync to HealthKit the moment they complete. HKObserverQuery fires in background. App imports silently — GPS trace, HR, pace, splits, calories.
Auto · background
Primary
iPhone GPS
In-app GPS run tracker (for users without Watch). Records live, writes to HealthKit on save — same observer picks it up, no double-import.
In-app · auto-saved
Secondary
Garmin / Wahoo
Third-party devices that write to Apple Health (via their own apps). HKObserverQuery catches these too — no additional integration needed at MVP.
Via HealthKit bridge
Fallback only
Manual Log
Pool swim, gym session, travel run without phone. User enters type, duration, distance, perceived effort. Clearly positioned as "didn't have your watch?" flow.
Explicit fallback
② Background import pipeline
01
HKObserverQuery
Background delivery enabled. iOS wakes app when new HKWorkout, HKQuantitySample (weight, HR) added to Health.
→
02
HKAnchoredObjectQuery
Incremental fetch — only pulls data added since last anchor. Efficient, no duplicate imports.
→
03
Dedup + map
Check UUID against existing activities. Map HKWorkout → activities row + run_details if GPS present.
→
04
Link to plan
If a planned session exists for today and workout type matches — auto-mark session complete.
→
05
Cancel notification
Cancel pending training reminder for this activity. User never sees a stale prompt.
→
06
Surface to Dashboard
"Nice work — we got your 5.2km run" card. One tap to add notes or link to cycle phase.
③ Smart notifications — state-aware before every delivery
Every notification checks current state before it reaches the user. If the action is already done, the notification is cancelled — not just hidden, permanently removed from the queue.
